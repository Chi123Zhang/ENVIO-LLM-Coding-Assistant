# ORCCA Research Assistant: question-first workflow

The homepage retains optional Document Coding. Start current research work in **ORCCA Workflow**. The website and exports are in English.

1. Expand **0 · Research question and data requirements**. Name a hypothesis or question, choose a planning route and analysis unit, and optionally define measures and time coverage. Save the question. H3 is the default; custom questions are planning metadata, not automatically implemented statistical models.
2. Load a synthetic H3 project in **1 · Project inputs**. Public research uploads remain disabled. A private installation can use the existing server-gated workbook intake; do not upload study files to Streamlit Cloud.
3. In **2 · Data review**, inspect required components, source availability and next steps. A file being present does not validate a measure. Missing definitions, unavailable outcomes and unestablished temporal order remain explicit.
4. In **3 · Evidence and completion**, search with BM25 or the separately available hybrid backend. Only original evidence enters source memory. Inspect passages and their exact locations. The optional local Qwen demonstration reruns BM25 and shows genuine saved model responses on three handwritten fictional examples; it does not perform live cloud generation.
5. In **Evidence Completion**, inspect a source-based candidate, make an explicit review decision and create a derived project version. Unsupported values remain unknown. Original data are preserved. Statistical scenarios are not accepted source corrections.
6. Generate current findings in **4 · Findings and review**. Review them independently of model suggestions. Export accepted findings only, or uncheck that option to export a clearly labelled pending-review report in **5 · Export**.

## What updates

Changing and saving the question creates a new project version, reruns the source inventory and clears finding approvals. Changing/removing files invalidates the current project until it is reloaded. A confirmed source completion creates another derived version. Queries and retrieval methods have their own fingerprints; obsolete retrievals are not presented as current. Switching pages keeps the same current project within the browser session. There is no background monitoring or persistence guarantee after a session ends.

## What this release establishes

The platform supports an end-to-end review process. It does not establish an H3 mediation effect, recover suppressed deaths, validate a general imputation model or demonstrate a RAG accuracy/time gain. The model recording deliberately preserves an abstention despite an explicit fictional date, so its limitations are visible. There are no model-generated human labels. No new institutional security certification is claimed.

The source-only pilot, audit pages, findings, reviewed completion, optional interview tools and exports remain available. Core filenames, codebook prompts and model settings are preserved. No real Tracker, dictionary, attendance records, meeting excerpts, private reviews or credentials are included in this release.
